Author: Aakash Kedia <a-kedia@ti.com>
Date:   Sat Jul 4 15:45:51 2026 +0530

    am26xxx: dthe/aes: Fix AES driver bugs for compliance testing
    
    Fix three bugs in the DTHE AES driver identified during AES compliance
    testing:
    
    1. Fix decrypt data length alignment check: restrict the 16-byte
       alignment requirement to ECB and CBC modes only. Stream cipher
       modes (CTR, CFB, GCM, CCM) support any data length and must not
       be rejected for non-block-aligned decrypt operations
    
    2. Remove AAD 4-byte alignment restriction: the condition
       if((ptrParams->aadLength%4U)==0U) incorrectly skipped AAD
       processing for non-4-byte-aligned AAD lengths in GCM/CCM modes
    
    3. Add DTHE_AES_GHASH_ONLY_MODE support for GMAC (GCM with
       zero-length plaintext):
       - Allow GHASH_ONLY_MODE with dataLenBytes=0 in one-shot validation
       - Guard against NULL plaintext/ciphertext pointer dereference when
         no data is present
       - GHASH_ONLY_MODE skips the data processing loop and only
         processes AAD before reading the authentication tag
    
    Fixes: TIFSMCU-5455
    Signed-off-by: Aakash Kedia <a-kedia@ti.com>

    am26xx/f29xx: crypto/util: Add DigestInfo to PKCS#1 v1.5 sign padding
    
    Crypto_PKCSPaddingForSign built EM as 0x00||0x01||PS||0x00||Hash,
    omitting the ASN.1 DER DigestInfo header required by EMSA-PKCS1-v1_5
    (RFC 8017 Section 9.2). Cert_Auth_RSAVerify expects the DigestInfo
    header, so signatures produced by this helper did not match the
    format its callers rely on for verification.
    
    - Add DigestInfo tables for SHA-1/256/384/512
    - Rewrite the function to emit the full RFC 8017 Section 9.2 encoding
    - Add HASH_ALG_SHA2_384 to support SHA-384 padding
    - Remove Crypto_PKCSPaddingForMessage: EME-PKCS1-v1_5 encryption
      padding with zero callers in the codebase; RSA encryption examples
      use raw/unpadded RSA instead
    
    Fixes: TIFSMCU-5721, TIFSMCU-5722
    
    Signed-off-by: Aakash Kedia <a-kedia@ti.com>
